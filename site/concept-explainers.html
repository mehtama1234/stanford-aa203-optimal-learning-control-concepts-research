State & dynamics — does the model capture the next step?

the hidden quantity

Before any optimization: does the state carry enough to predict what happens next, does the assumed physics match the real world, can the actuator actually deliver the move, and does the window look far enough ahead?

State

Object it changesthe information vector (position and velocity, or other measurements) passed to the controller each step
Hidden quantity measuredwhether the state contains all the information needed to predict the next state given the chosen action (the Markov property)
Math objectp(x_{k+1} | x_k, u_k) is independent of history; state x_k satisfies the Markov condition
Why it worksif you omit a quantity from the state that changes the physics, cost, or feasibility of the next step, the controller cannot see how its action will land; without velocity, a position-only controller cannot tell it is building speed and overshoots

Dynamics

Object it changesthe bridge from command to outcome — the rule predicting the next state
Hidden quantity measuredthe match or mismatch between the assumed dynamics and the real dynamics that govern motion
Math objectx_next = f(x, u); controller assumes f but real motion follows f_real
Why it worksbecause the controller gains are computed assuming a specific dynamics rule, a wrong rule means the gains are tuned for an incorrect model and every move is miscalibrated, making corrections underpowered or oversized

Action / Control Input

Object it changesthe command sent to an actuator — the real force, torque, or voltage the motor can actually deliver
Hidden quantity measuredwhether the motor is clipped (delivering less than requested) and how much slower things now move
Math objectu_clipped = clip(u_desired, -u_max, +u_max)
Why it workswhen the actuator's limit clips the delivered force below what the plan asked for, the state moves by less each step, so the time to reach any goal stretches inversely with how tight the limit is, until below a threshold where the goal becomes unreachable
deep diveopen →

Horizon

Object it changeshow many future steps the optimizer reasons about — the window it optimizes over
Hidden quantity measuredwhether the first optimized action will be blindsided by consequences lurking just outside the window boundary
Math objectfinite-horizon cost J = Σ(k=0 to N-1) c_k; myopic when N is too small to see decision-changing futures
Why it worksa longer window lets costs far into the future feed back to influence today's action, so the controller brakes before the wall instead of after seeing it
deep diveopen →

Policy

Object it changesthe decision rule — a function or lookup table that reads the current state and outputs an action (deterministic or probabilistic)
Hidden quantity measuredwhat happens in the next step — which state you will face after this action completes, feeding back into the rule again
Math objectu = π(x) or u ~ π(·|x) (deterministic or stochastic)
Why it worksa policy survives repeated use in a closed loop only if each action it chooses leaves the next state in a situation where the same rule produces a reasonable next action; planning the whole sequence once gets this wrong, but replaying a simple rule every step with feedback corrects for model error

The specification — what the one number really rewards

the hidden quantity

Everything downstream optimizes a single scalar you wrote by hand. The hidden quantity is whether that scalar's trade-offs and loopholes actually match your intent.

Objective / Cost Function

Object it changesthe scoring rule — a weighted sum of error and effort that ranks all possible trajectories from worst to best
Hidden quantity measuredthe exchange rate between competing goals — how much error is worth how much control effort
Math objectJ = ∑_k [state_error_k^2 + R·control_effort_k^2] where R is the weight on effort
Why it workswriting the cost as a weighted sum forces the optimizer to trade off speed against gentleness; raise the effort weight and the controller automatically becomes gentler because aggression now costs more in the one number it minimizes
deep diveopen →

Reward

Object it changesthe numerical proxy signal that defines what the agent optimizes
Hidden quantity measuredwhether the proxy has a loophole that the learner can exploit without achieving the real intent
Math objectr_total = r_goal + r_bonus + r_penalty, where each term is a design choice
Why it worksthe learner optimizes the exact number you write; if that number rewards a shortcut that does not satisfy your real goal, the learner finds and pursues the shortcut instead

Cost-to-go — the future cost stored at a state

the hidden quantity

Attach one number to every state: the best remaining cost (or reward) from here on. Store it, reuse it, and any single move can be judged using only its neighbors' numbers.

Value Function

Object it changesthe single number attached to each state—the total remaining cost under optimal behavior
Hidden quantity measuredwhich direction to move when all adjacent immediate steps have the same cost
Math objectV(x) = min_u [ c(x,u) + γ × V(f(x,u)) ]
Why it workswhen every move costs the same right now, comparing (immediate cost + value of destination) across neighbors creates a virtual landscape you can descend; the value at each cell encodes the invisible fact of how far away the goal is
deep diveopen →

Bellman Recursion

Object it changesthe value function V(x) — one stored number per state representing the best cost-to-go from that state to the goal
Hidden quantity measuredwhether the stored value at a neighboring state is consistent with what physics-plus-cost says it should be (the fixed-point gap)
Math objectV(x) = min_a [c(x,a) + γ V(f(x,a))]
Why it worksreusing a stored future-cost number at a neighboring state avoids recalculating the entire path from scratch; repeating this backup until stored values stop changing ensures all values agree with their own local physics, so the policy stays consistent everywhere
deep diveopen →

Dynamic Programming

Object it changesthe decision rule — replaced by a lookup table of optimal actions indexed by state
Hidden quantity measuredthe cost-to-go from each state (the value), which shrinks by exactly the discount factor with each backward sweep
Math objectV(s) = min_a [c(s,a) + γ·V(s'); π(s) = argmin_a [c(s,a) + γ·V(s')]
Why it worksby storing the future cost at every state and comparing immediate moves using only that number, the problem breaks into state-indexed pieces; the discount factor guarantees that each update shrinks error, so sweeping through all states repeatedly converges
deep diveopen →

Stochastic Dynamic Programming

Object it changesthe backward cost recursion when next states are uncertain
Hidden quantity measuredthe probability-weighted average of future costs across all possible landings
Math objectV(x) = min_u [ c(x,u) + γ × Σ_x' P(x'|x,u) × V(x') ]
Why it workswhen a move lands you in several places with different probabilities, averaging their costs at each step naturally balances catastrophic outcomes (rare but severe) against normal outcomes (likely but small) in a single backward pass
deep diveopen →

Reinforcement Learning

Object it changesthe learned Q-table (action-value estimates from each state)
Hidden quantity measuredhow much total discounted reward lies ahead if you take this action now
Math objectQ(x,u) ← Q(x,u) + α[r + γ max_{u'} Q(x',u') − Q(x,u)]
Why it worksevery try produces a return (total payoff from this step onward) that you can observe; the algorithm averages these returns into a stable estimate, so repeated exposure to the same move from the same state reveals its true payoff
deep diveopen →

Value-Based RL

Object it changesthe Q-value scoreboard—the estimated future return for each state-action pair
Hidden quantity measuredhow much of the total reward from the goal is attributable to taking this move now versus all moves that follow
Math objectQ(s,a) ← Q(s,a) + α [ r + γ max_{a'} Q(s',a') − Q(s,a) ]
Why it worksafter each move you observe reward and land in a new state; nudging the old score toward (immediate reward + discounted best-next score) creates a chain reaction where one rewarding goal ripples backward to make distant earlier moves look valuable
deep diveopen →

Policy Optimization

Object it changesthe decision rule's parameters — the probabilities or weights that determine which action gets chosen in each state
Hidden quantity measuredthe advantage of each tried action — whether it beat the expected baseline return, signaling whether to raise or lower its probability
Math objectπ_new(a|x) ∝ π_old(a|x) · exp(η · (return - baseline(x)))
Why it worksnudging the rule toward actions that surprised you on the upside and away from those that disappointed you lets you learn without needing to know the scores of untried actions, so you can optimize continuous infinite-dimensional action spaces

Shadow prices & stationarity — the first-order optimality signals

the hidden quantity

The invisible price tag on a state or a constraint: how much total cost moves if this state, or this limit, shifts by one unit — and whether the gradient has flattened to zero.

Costate / Adjoint Variable

Object it changesthe dual variable λ(t) running backward in time — a sensitivity number attached to each state coordinate
Hidden quantity measuredhow much the total remaining cost changes if the state nudges by a tiny amount right now (the shadow price of that state)
Math objectλ[t] = ∂L/∂x[t] + A^T λ[t+1]; u[t] = -B^T λ[t+1]
Why it worksthe costate carries backward from the final-time cost the price of each earlier state decision; because it accumulates how much each nudge ripples into the future, you can evaluate any action locally using just the immediate cost minus the costate benefit, without recomputing the entire downstream path
deep diveopen →

Hamiltonian for Optimal Control

Object it changesthe state-motion direction at each instant — what to push now
Hidden quantity measuredthe shadow price of moving the state by one unit from now onward — the costate, how much future cost will drop if this state improves
Math objectH(x,u,p) = L(u) + pᵀ·f(x,u); u* minimizes H over legal actions
Why it worksby bundling the immediate cost of an action with the backward-computed price of what it moves you into, every instant can make a locally correct choice using only two numbers: state and costate, without replanning the whole future
deep diveopen →

Gradient and First-Order Condition

Object it changesthe search direction — from random guessing to downhill stepping
Hidden quantity measuredwhether a downhill direction exists (gradient ≠ 0) or whether the point is stationary (gradient = 0)
Math object∇J = 0 at stationarity; step u_next = u - α·∇J
Why it workseach step downhill multiplies the error by a factor less than 1 (the cost curve's discount-like slope shrinkage), so repeated stepping guarantees convergence to a critical point where the gradient vanishes
deep diveopen →

Static Optimization

Object it changesthe choice of one feasible point (the power setting, control magnitude, or design parameter)
Hidden quantity measuredwhether the optimal point lives at level ground (zero gradient) or is pinned against an active constraint boundary
Math objectAt optimum: ∇J(z*) = 0 or z* lies on an active constraint; KKT condition: ∇J + λ∇g = 0 with λ≥0
Why it worksthe cost landscape has a bottom; if that bottom is outside the legal set, the boundary physically stops you there; the best legal point is either where the ground is level or where a wall prevents you from going downhill
deep diveopen →

Constraints

Object it changesthe set of legal plans — the subset of all possible trajectories that do not violate hard rules on state, action, or time
Hidden quantity measuredwhether a rule is active (the plan is right on the boundary) or slack (the plan has margin to spare)
Math objectg(x, u) ≤ 0 for all time (inequality constraints); equality if active
Why it worksa hard constraint removes options by forbidding the plan that ignores the rule, forcing the optimizer to find a different path that obeys the boundary; soft penalties can be traded away, but hard constraints cannot, so the best legal plan costs more than the unconstrained answer
deep diveopen →

The first variation — optimizing a whole path at once

the hidden quantity

Treat the entire trajectory as the unknown. The hidden signal is whether any physics-legal wiggle of the path lowers total cost; when no wiggle helps, the path is optimal.

Calculus of Variations

Object it changesa trajectory through time — the entire sequence of states and actions the system will follow
Hidden quantity measuredwhether a small admissible bump in the path changes the total cost (the first variation)
Math objectEuler equation: d/dt[∂L/∂ẋ] - ∂L/∂x = 0
Why it worksif every tiny perturbation the physics allows makes the cost the same or worse, the path is locked in place and cannot be improved by nudging; this condition produces a differential equation that only certain shapes (like straight lines) can satisfy
deep diveopen →

Indirect Methods

Object it changesthe search problem — replaced by a small set of optimality equations to solve
Hidden quantity measuredwhether the equations that define an optimal path have been written down correctly and can be solved faster than brute-force search
Math objectPontryagin conditions: x·=f(x,u), p·=-∇_x H, ∇_u H=0 at optimality; solve by shooting (guess p(0), integrate forward, measure boundary miss, correct)
Why it worksinstead of checking trillions of possible paths, write down what an optimal path must satisfy (state equation, costate equation, stationarity); solving a few equations is incomparably faster than searching the vast space
deep diveopen →

Optimal Control Problem

Object it changesthe action sequence — the full chain of forces from now until the horizon, chosen to minimize total cost and respect all constraints
Hidden quantity measuredthe knock-on effect of each move — how this step's action reshapes what options are available in the next step
Math objectmin_{u_0,...,u_{T-1}} ∑_t c(x_t,u_t) s.t. x_{t+1}=f(x_t,u_t), bounds(u,x), x_T∈S_terminal
Why it workschoosing the whole sequence at once instead of greedily picking the best immediate move lets you see ahead and avoid building speed or commitments that become impossible to undo later
deep diveopen →

Trajectory Optimization

Object it changesthe forces applied at each time step across the entire horizon
Hidden quantity measuredhow much each early force ripples forward through physics to affect later states and later costs
Math objectminimize J = Σ_k (f_k)² subject to x_{k+1} = A x_k + B f_k, x_0 = [0,0], x_T = [1,0]
Why it workswhen you make all future forces into a single choice rather than a series of local rules, the solver can see how nudging an early force changes both the state it creates and the cost needed to recover from that state, trading off steps together instead of greedily
deep diveopen →

Numerical defect — the honesty of a discretized path

the hidden quantity

To optimize a continuous path on a computer you chop it into samples. The hidden quantity is the defect: where the sampled path secretly violates physics between the points you checked.

Direct Transcription

Object it changesthe continuous trajectory — replaced by a finite grid of state and control samples
Hidden quantity measuredthe gap between what physics predicts and what the grid claims at each step (the defect)
Math objectdefect_k = x_k+1_actual - (x_k + dt·f(x_k, u_k))
Why it worksby writing every state and control as a decision variable and adding constraints that force neighbors to obey the physics update rule, the optimizer can directly find a trajectory that satisfies the dynamics everywhere on the grid
deep diveopen →

Collocation

Object it changesthe smooth curve connecting knot points — the path parameterized by polynomial or piecewise pieces between discrete waypoints
Hidden quantity measuredwhether the curve's slope at interior sample points actually matches what the physics predicts (the defect)
Math objectdefect_k = x_dot_curve(t_k) - f(x_k, u_k) = 0 at each knot k
Why it worksenforcing that the drawn path's slope at interior sample points must equal what the dynamics allows catches collisions and momentum lies that endpoint-only checking misses, because a smooth curve can hide a violation between two checked points unless you force interior honesty
deep diveopen →

Shooting Methods

Object it changesthe launch control values (the unknown parameters guessed at the start)
Hidden quantity measuredthe endpoint error as a function of the launch guess (the Jacobian sensitivity)
Math objectu_new = u_old − J⁻¹ r, where J = ∂x_final/∂u_launch and r = x_final − x_target
Why it worksrolling physics forward from a guessed control produces an endpoint miss; inverting the sensitivity (how much the miss changes per unit control change) tells you exactly how to adjust the launch to correct the miss
deep diveopen →

Convergence & trust — whether an iteration has settled

the hidden quantity

Iterate a rule (backward in time, or by re-fitting a local model); the hidden quantity is whether it has stopped changing or is still trustworthy. Once it settles, one constant law works forever.

LQR

Object it changesthe control law — replaced by a single fixed gain that multiplies the measured state
Hidden quantity measuredwhether the backward cost-to-go has stopped changing at each step going backward in time
Math objectsteady-state Riccati: K = (R+BᵀPB)⁻¹BᵀPA; optimal u = -Kx for far-from-end steps where P has converged
Why it workssquared cost preserves its bowl shape when passed backward through linear dynamics, so the optimal feedback law collapses to two fixed multipliers you compute once and reuse forever, and sufficiently far from the horizon end those multipliers stop changing
deep diveopen →

Local Quadratic Approximation

Object it changesthe cost landscape — replaced by a simple bowl-shaped quadratic fit at one point
Hidden quantity measuredhow far from the fitting point the quadratic's error stays small enough to trust the solution
Math objectTaylor fit: J_quad(x) ≈ c₀ + c₁·x + c₂·x²; error grows as true curve's curvature drifts from frozen quadratic curvature
Why it worksby freezing the cost model to its local shape (constant, slope, curvature), you can solve it as LQR in one cheap pass; but you must stay close in because the bowl's curvature does not follow the true curve's changing bends
deep diveopen →

Stability Under Replanning

Object it changesthe Lyapunov function (the distance-to-goal yardstick measured after each replanned move)
Hidden quantity measuredwhether the closed-loop yardstick is provably shrinking or staying flat (never rising)
Math objectV(x_{k+1}) ≤ V(x_k) with V(x*)=0 at goal; enforced by terminal cost or terminal set
Why it worksif you can find a measurement of progress that provably goes down (or stays at zero) after every real applied move, the loop must reach the goal in finite time; terminal costs and sets ensure the yardstick shrinks
deep diveopen →

Feasibility & reachability — whether a legal future still exists

the hidden quantity

Not cost but existence: is there any legal move left at all, and will today's move leave tomorrow's problem solvable rather than painting you into a corner?

Feasibility

Object it changesthe problem structure — split into existence and then optimality
Hidden quantity measuredwhether the feasible set (all sequences obeying constraints and dynamics) is empty or non-empty
Math objectminimize J(u) subject to: c(x_k, u_k) ≤ limits; first check if feasible set is ∅
Why it worksby checking whether any legal trajectory exists before trying to minimize cost, the system avoids wasting computation on an empty set and can trigger recovery (fail-safe) when no legal action remains
deep diveopen →

Reachability

Object it changesthe safe region — the set of all states from which a legal control sequence can reach the goal despite constraints and adversarial disturbances
Hidden quantity measuredwhether the laws of motion still allow escape — the true boundary between control-enabled and inevitable-fate, invisible in space alone but encoded in dynamics
Math objectBackward reachable set R_k = {x : ∃u, ∀w, f(x,u,w)∈R_{k-1}} with R_0={x_goal}
Why it worksworking backward from the goal to ask 'which states could have reached here?' builds a hard safety boundary that no planner can cross; a state outside it is doomed no matter what controls you apply, because physics forbids escape
deep diveopen →

Recursive Feasibility

Object it changesthe feasibility certificate — the proof that each applied move leaves tomorrow's planning problem solvable, not just today's
Hidden quantity measuredwhether the successor state belongs to a terminal safe set from which the next horizon-constrained plan is guaranteed to exist
Math objectIf x_{k+1}^predicted ∈ X_terminal_safe, then ∃ feasible plan at step k+1, ensuring recursive feasibility: feasibility(k) ⟹ feasibility(k+1)
Why it worksa move that looks legal right now can paint you into a corner where no next move is legal; demanding that your first move's predicted outcome lands in a region from which braking still works guarantees you never walk into that trap
deep diveopen →

Model Predictive Control

Object it changesthe control sequence — replaced by a receding-horizon re-solve that executes only the first move, then re-measures and replans
Hidden quantity measuredwhether the next replanning step will remain feasible (solvable) from the successor state that this move produces
Math objectmin_{u_0,...,u_{H-1}} ∑ cost(x_t, u_t) s.t. x_{t+1}=Ax_t+Bu_t, bounds, then apply u_0* and resolve from measured x_1
Why it worksreplanning every step with a short horizon lets you see the next few moves but forces you to hand over a good state to tomorrow's solver; if the horizon is long enough to foresee danger zones, you never walk into a corner that has no legal exit
deep diveopen →

Distribution shift & coverage — has the model seen what it will face?

the hidden quantity

A learner trained on one set of states is deployed on the states it itself creates. The hidden quantity is the gap between the states it was taught and the states it will actually visit.

Behavioral Cloning

Object it changesthe learned control rule — a function mapping state to action, fit to expert demonstrations
Hidden quantity measuredthe distribution of states the cloned model will never have seen, and how far it can extrapolate before guessing wildly
Math objectu_clone = w_pos * x_pos + w_vel * x_vel (linear fit to expert (state, action) pairs)
Why it worksa straight-line fit learns exactly what the expert did within the training band and is forced to extrapolate beyond it, so error compounds in closed loop as the model's own mistakes move it into unfamiliar territory where it has no idea what to do
deep diveopen →

Imitation Learning

Object it changesthe policy rule — replaced by a supervised learner fit to expert demonstrations
Hidden quantity measuredwhether the learner has seen expert labels for the states it creates when rolling out on its own, not just the expert's home region
Math objectDAgger: iterate {roll π_learner, collect S_visited, query expert labels for S_visited, add to training set, refit}
Why it worksasking the expert only about states in their own demonstrations leaves a gap: when the learner's own error moves it into new territory, it has no teacher for recovery; feeding back the learner's visited states to the expert closes that gap
deep diveopen →

Distribution Shift in Imitation

Object it changesthe training dataset — shifted from expert-visited states to learner-induced states
Hidden quantity measuredwhether the next state the learner will see comes from the expert's distribution or the learner's own induced distribution
Math objectP_expert ≠ P_learned; training on P_expert, deploying on P_learned
Why it workseach small error by the learner moves it into a state the expert rarely demonstrated, so the learner's next prediction has no training examples to lean on, making the error worse and pulling it further into unfamiliar territory
deep diveopen →

Model-Based RL

Object it changesthe learning algorithm — replaced by a learned forward model that you plan on instead of testing every move
Hidden quantity measuredwhether the learned model's coverage of state-action space is large enough that planning on it reaches unseen goals
Math objectmodel transition table T[s,a]→s'; value iteration: V(s)←min_a[cost(s,a)+γ·V(T[s,a])]; extract policy greedily
Why it worksone observed transition can be reused in thousands of imagined paths through the learned model, multiplying the value of each real experience; whereas trial-and-error learns one backup per step, planning re-asks 'what if I string these transitions together this way' many times on the same batch of data
deep diveopen →

Exploration

Object it changesthe action selection rule — from pure greedy to deliberate randomness
Hidden quantity measuredwhether the learner has seen enough evidence of the true value of each action to trust its estimate
Math objectselect random_action with probability ε; select greedy argmax with probability 1-ε
Why it worksrandom moves now cost immediate reward but reveal the consequences of actions the greedy rule would never try, so later moves can be based on real data about high-value regions the learner would otherwise never reach
