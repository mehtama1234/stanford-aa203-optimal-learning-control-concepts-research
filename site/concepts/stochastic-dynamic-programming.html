Stochastic Dynamic Programming

Dynamic programming when the next state is uncertain and future value must be averaged over possible outcomes.

01 · the ordinary pressure

Why this idea has to exist

A controller often does not know exactly what will happen after an action because noise, disturbances, or environment changes intervene.

The tempting shortcut is simple: Plan for the most likely next state only. But that shortcut breaks because rare but costly outcomes can dominate safety and expected cost.

02 · the object

What the math keeps track of

The controller keeps track of an expected-value bellman equation. This answers a practical question: use it when the same action can lead to several next states.

The operation is concrete: Add immediate cost to the expectation of next-state value under the transition distribution.

04 · boundary

Where the idea stops working

The uncertainty model must describe the relevant randomness.

If that boundary is crossed, the visible failure is this: the policy is brittle because it ignores low-probability dangerous states.
