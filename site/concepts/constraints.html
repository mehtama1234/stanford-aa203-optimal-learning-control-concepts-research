Constraints

Rules the solution must obey even if breaking them would reduce the written cost.

01 · the ordinary pressure

Why this idea has to exist

Physical systems have limits: actuators saturate, obstacles block motion, temperatures must stay bounded, and budgets run out.

A common wrong first move is: Add a soft penalty and hope the optimizer avoids illegal behavior. It fails when some violations are not tradeoffs; a robot collision or infeasible thrust command is simply not allowed.

02 · the object

What the math keeps track of

The working object is equality and inequality constraints over states, actions, and trajectories. Use it when you need to ask what the controller is never allowed to do, even to improve the score.

What the object does: Restrict the feasible set before choosing the best point inside it.

03 · read it with your hands

What to inspect first

Before naming the method, point to equality and inequality constraints over states, actions, and trajectories in the setup. Ask what a person could measure, command, update, price, or forbid in one small run.

Now apply one command or one update. Restrict the feasible set before choosing the best point inside it. After that operation, ask what changed in the next state, the path, the value, the constraint set, the policy, or the learned model. If nothing concrete changes, the explanation is still only a label.

The world check is the example: A drone path that clips through a wall may have low energy cost but is not a candidate path. Try the same question on another car, drone, rover, robot arm, or reward signal. The concept should still name what changes, what is paid for, and what can fail.

04 · one concrete run

Work it through before naming the formula

A robot arm may find a low-energy path by swinging through a shelf. The cost likes it; the world does not. Constraints are the hard walls in the problem: joint limits, torque limits, collision surfaces, battery reserve, and safe speed.

the actual math, one level deeper

A constraint is an equation or inequality such as g(x,u) <= 0. A candidate path is not admissible unless every required constraint is satisfied at the relevant time.

05 · boundary

Where the idea stops working

The constraint must describe the actual safety or physical boundary closely enough.

When that condition fails, look for this visible break: a controller finds a mathematically cheap path through a forbidden region.

Recognize it in a new problem: Ask what the controller is never allowed to do, even to improve the score.
