Formula Reader

A formula is a machine for doing one job. Read it by asking what it operates on, what gets changed, what future is being priced, and where the reading becomes false.

The symbols in AA203 are easy to misread as decoration. They are not. Each formula is a small machine: put in a state, an action, a cost, a model, or a rollout; get out a next state, a price on the future, a constraint check, or a policy update.

The reading order is always the same. First ask what real situation forced the formula to exist. Then identify the object it stores. Then name the operation it performs. Only after that should the symbols matter.

Dynamics

x_next = f(x, u)

A command is not a teleport. If the car turns the steering wheel, the next state depends on current speed, tire grip, and heading.

The object: The object is a transition rule from present state and action to next state.

The operation: Feed in the state and action, then propagate the consequence one step forward.

If a drone has upward velocity 1 m/s and the controller cuts thrust, the next height may still rise for a moment while velocity falls. Dynamics explain that delay.

where it fails

If the model ignores wind, ice, contact, or actuator lag, the controller prices a future that the real system will not follow.

Objective

total cost = path costs + terminal cost

A future is not good just because it reaches the goal. It may use too much fuel, hit a wall, arrive late, or end with unsafe speed.

The object: The object is a cost functional: a rule for scoring a whole history.

The operation: Add the cost paid along the path and the cost left at the end.

A rocket landing score can add fuel burn every second, then add a large final penalty for height error and touchdown speed.

where it fails

If the written cost omits damage or risk, the optimizer can choose a future that is cheap on paper and bad in the world.

Bellman Recursion

V(x) = best action of cost now + value next

The controller needs to judge a current action by the future state it creates, without listing every complete future.

The object: The object is a value function: future cost stored at each state.

The operation: For each action, add immediate cost to the value of the next state, then choose the best sum.

A rover may pay one extra minute to avoid sharp rocks because the next state after the rocky shortcut has damaged wheels and worse future value.

where it fails

If the state is missing hidden information, the value table attaches the wrong future price to that state.

Hamiltonian

H = stage cost + costate times dynamics

A small action change affects cost now and also pushes the whole future state history.

The object: The object is a local package that combines immediate cost with a backward price on state motion.

The operation: Price a control change by adding what it costs now to what its state change costs later.

For a rocket, more thrust burns fuel now but changes future velocity. The costate says how valuable that velocity change is later near touchdown.

where it fails

Hamiltonian conditions are necessary conditions; they can identify a candidate path without proving it is the best global path.

MPC

solve horizon, apply first action, measure, repeat

A long plan becomes stale after the first gust of wind, moving car, or bad state estimate.

The object: The object is a finite-horizon problem rebuilt from the current measured state.

The operation: Solve, use only the first command, shift the horizon, and solve again.

A car plans five seconds ahead but executes only 0.1 seconds of steering and throttle before traffic is measured again.

where it fails

A short horizon without terminal protection can make a legal first move that leaves no legal move next time.

Policy Gradient

move policy parameters toward higher return

Sometimes the learner has no clean model or action labels, only rollouts and delayed reward.

The object: The object is a parameterized policy that chooses actions from observations or states.

The operation: Use rollout returns to nudge the policy toward actions that led to higher long-run reward.

A grasping robot tries many wrist angles; successful lifts increase the probability of similar actions in similar poses.

where it fails

Sparse reward, unsafe exploration, or random lucky rollouts can push the policy in the wrong direction.
