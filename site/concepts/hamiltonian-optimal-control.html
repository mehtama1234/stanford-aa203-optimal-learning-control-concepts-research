Hamiltonian for Optimal Control

A combined expression that packages immediate cost with how actions move the state into future cost.

01 · the ordinary pressure

Why this idea has to exist

An action must be judged both by what it costs now and by how it changes the state that future costs depend on.

The tempting shortcut is simple: Choose the action with the smallest immediate cost. But that shortcut breaks because the cheap action now can steer the state into an expensive region.

02 · the object

What the math keeps track of

The controller keeps track of the hamiltonian in an optimal-control necessary condition. This answers a practical question: use it when a local action must be priced by immediate and future state effects together.

The operation is concrete: Combine stage cost, dynamics, and costate sensitivity, then choose controls that satisfy the necessary condition.

03 · read it with your hands

What to inspect first

Point to the physical record or mathematical object before naming the method. In this concept, that object is the hamiltonian in an optimal-control necessary condition. Ask what a person could measure, command, update, price, or forbid in one small run.

Now apply one command or one update. Combine stage cost, dynamics, and costate sensitivity, then choose controls that satisfy the necessary condition. After that operation, ask what changed in the next state, the path, the value, the constraint set, the policy, or the learned model. If nothing concrete changes, the explanation is still only a label.

The world check is the example: A rocket burn costs fuel immediately but may reduce future position error; the Hamiltonian puts both effects in one local calculation. A reader should be able to replace that setup with another car, drone, rover, robot arm, or reward signal and keep the same control question alive.

04 · one concrete run

Work it through before naming the formula

More thrust costs fuel now and changes velocity later. The Hamiltonian puts both facts in one local expression: immediate cost plus the costate's price for how the dynamics move the state.

the actual math, one level deeper

H(x,u,lambda) combines stage cost with lambda times dynamics. Stationarity with respect to u gives a necessary condition for a locally optimal control.

05 · boundary

Where the idea stops working

It gives necessary conditions under model and smoothness assumptions, not automatic global optimality.

If that boundary is crossed, the visible failure is this: a trajectory satisfies local equations but is not the best or violates practical constraints.

Recognize it in a new problem: Use it when a local action must be priced by immediate and future state effects together.
