Indirect Methods

Solve an optimal-control problem by first deriving equations that an optimal trajectory must satisfy.

01 · the ordinary pressure

Why this idea has to exist

Instead of searching over all paths directly, use mathematical structure to reduce the search to conditions of optimality.

A common wrong first move is: Discretize everything immediately and hand the whole problem to a numerical optimizer. It fails when direct search can be large and blind to the state and cost sensitivities already implied by the equations.

02 · the object

What the math keeps track of

The working object is necessary conditions such as state, costate, and stationarity equations. Use this lens when the analytic necessary conditions are central to the method.

What the object does: Derive the boundary-value problem implied by optimality and solve those equations.

03 · read it with your hands

What to inspect first

Before naming the method, point to necessary conditions such as state, costate, and stationarity equations in the setup. Ask what a person could measure, command, update, price, or forbid in one small run.

Now apply one command or one update. Derive the boundary-value problem implied by optimality and solve those equations. After that operation, ask what changed in the next state, the path, the value, the constraint set, the policy, or the learned model. If nothing concrete changes, the explanation is still only a label.

The world check is the example: For a spacecraft transfer, the indirect method derives equations for both the state path and the shadow price of state errors. Try the same question on another car, drone, rover, robot arm, or reward signal. The concept should still name what changes, what is paid for, and what can fail.

04 · one concrete run

Work it through before naming the formula

A rail cart must move from x(0)=0 meters to x(2)=1 meter while using little effort. The dynamics are x_dot = u, and the running cost is 0.5*u^2. A direct method would choose many grid values for x and u and enforce the dynamics between grid points. An indirect method first asks what any smooth optimum must obey. It introduces a costate p(t), builds the Hamiltonian H = 0.5*u^2 + p*u, and sets the local stationarity condition dH/du = u + p = 0. That gives u = -p. The costate equation gives p_dot = 0, so p is constant. Now the whole family of candidate paths is controlled by one missing number. If p(0) = -0.3, then u = 0.3 and x(2)=0.6, so the cart is 0.4 meters short. If p(0) = -0.7, then u = 0.7 and x(2)=1.4, so it overshoots by 0.4 meters. The boundary x(2)=1 picks p(0) = -0.5, hence u(t)=0.5 and x(t)=0.5*t. The indirect method did not search over every grid point; it derived the equations of a candidate optimum and then solved for the missing boundary value.

the actual math, one level deeper

The standard indirect pattern is derive first, solve second. From a continuous optimal-control problem, form H(x,u,p)=L(x,u)+p*f(x,u). Then write the necessary conditions: x_dot = partial H/partial p, p_dot = -partial H/partial x, partial H/partial u = 0, plus boundary conditions such as x(0)=0 and x(2)=1. In the rail-cart example, partial H/partial u = u+p=0 expresses control as u=-p, and p_dot=0 makes p constant. The boundary residual is r(p0)=x(2;p0)-1. Trying p0=-0.3 gives r=-0.4; trying p0=-0.7 gives r=+0.4; the root is p0=-0.5. The strength is a small structured boundary-value problem. The boundary is fragility: wrong derivation, bad initial costate guesses, nonsmooth constraints, or active path limits can make the equations hard to solve or make a necessary candidate look better than it really is.

05 · boundary

Where the idea stops working

It depends on correct derivation and can be sensitive to boundary guesses.

When that condition fails, look for this visible break: the equations are hard to solve numerically or describe only a local candidate.

Recognize it in a new problem: Choose this lens when the analytic necessary conditions are central to the method.
