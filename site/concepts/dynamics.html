Dynamics

The rule that says how the current state and action produce the next state.

01 · the ordinary pressure

Why this idea has to exist

Actions matter only through how they move the system. The controller needs a rule for that movement.

A common wrong first move is: Plan as if the action immediately creates the desired result. It fails when momentum, delay, friction, and coupling can make the result arrive later or in a different direction.

02 · the object

What the math keeps track of

The working object is a transition equation or differential equation. Use it when you need to if an action's effect depends on current motion, write the dynamics before optimizing.

What the object does: Propagate the state forward one step or through continuous time.

03 · read it with your hands

What to inspect first

Before naming the method, point to a transition equation or differential equation in the setup. Ask what a person could measure, command, update, price, or forbid in one small run.

Now apply one command or one update. Propagate the state forward one step or through continuous time. After that operation, ask what changed in the next state, the path, the value, the constraint set, the policy, or the learned model. If nothing concrete changes, the explanation is still only a label.

The world check is the example: Turning a steering wheel changes heading gradually; the car does not slide sideways to the target lane. Try the same question on another car, drone, rover, robot arm, or reward signal. The concept should still name what changes, what is paid for, and what can fail.

04 · one concrete run

Work it through before naming the formula

If a car is moving fast on ice, the same steering angle produces a different next state than it would on dry asphalt. Dynamics are the rule that carries a command through the body and the world. Without that rule, planning is only drawing wishes on a map.

the actual math, one level deeper

Dynamics can be written as x_next = f(x, u) in discrete time or dx/dt = f(x, u) in continuous time. The function is the claim about how action becomes motion.

05 · boundary

Where the idea stops working

The dynamics must match the time scale and operating region where the controller acts.

When that condition fails, look for this visible break: a model mismatch makes a plan look feasible on paper and fail on hardware.

Recognize it in a new problem: If an action's effect depends on current motion, write the dynamics before optimizing.
