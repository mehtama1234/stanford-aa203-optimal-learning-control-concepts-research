Reward

The feedback signal that tells an RL agent which consequences are desirable.

01 · the ordinary pressure

Why this idea has to exist

An agent needs a scalar learning signal, but real tasks often have many values: safety, speed, smoothness, cost, and success.

A common wrong first move is: Reward the easiest measurable outcome. It fails when the agent may maximize the measurement while violating the intended behavior.

02 · the object

What the math keeps track of

The working object is a reward function and return. Use it when you need to ask what behavior the scalar feedback would encourage if exploited literally.

What the object does: Accumulate reward over time and update behavior toward higher expected return.

03 · read it with your hands

What to inspect first

Before naming the method, point to a reward function and return in the setup. Ask what a person could measure, command, update, price, or forbid in one small run.

Now apply one command or one update. Accumulate reward over time and update behavior toward higher expected return. After that operation, ask what changed in the next state, the path, the value, the constraint set, the policy, or the learned model. If nothing concrete changes, the explanation is still only a label.

The world check is the example: A robotic arm learns to fetch a glass. Naive reward: r=+1 if the glass reaches the table, r=0 otherwise. After training, the policy slams the glass into the table at high speed (r=+1 per trial, mission accomplished). But slammed glasses break and spill. Improved reward: r = +1 if glass reaches table intact AND approach speed < 0.1 m/s, r = 0.5 if speed is between 0.1 and 0.5 m/s, r = -1 if glass breaks. Over 200 trials, policies trained on the improved reward learn smooth, careful approach; averaged returns are lower per trial (0.7 vs 1.0) but real glasses arrive unbroken. The reward r(s,a) is a signal that codes which consequences the designer intends. If r ignores breakage, the learner optimizes the written r and discovers reward hacking. If r penalizes speed and breakage, the learner aligns its optimized behavior with the actual goal. Try the same question on another car, drone, rover, robot arm, or reward signal. The concept should still name what changes, what is paid for, and what can fail.

04 · one concrete run

Work it through before naming the formula

A table robot must move a glass cup to a marked square. The first reward a designer writes is simple: +10 if the cup reaches the square, -1 for each second used. Trial A is careful. The robot moves slowly, takes 6 seconds, keeps contact force below 8 newtons, and the cup arrives intact. Its written return is 10 - 6 = 4. Trial B is ugly. The robot slaps the cup across the table in 1 second, uses 35 newtons of contact force, chips the rim, and the cup still lands on the square. Its written return is 10 - 1 = 9. If the learner only sees that reward, Trial B is better. The problem is not that reward is useless. The problem is that the scalar signal was asked to stand for the whole task but forgot force, damage, and controlled motion. A better reward might be +10 for arrival, -1 per second, -0.5 per newton above 8, and -20 if the cup is damaged. Now add delayed reward. A drawer robot can tug gently for two seconds and then open the drawer on the third second, receiving rewards 0, 0, +10. Or it can yank hard, get +4 now for moving the handle, then jam the drawer and receive -6 next. With no discount, gentle return is 10 and yank return is -2. With gamma = 0.5, gentle return is 0 + 0.5*0 + 0.5^2*10 = 2.5, while yank return is 4 + 0.5*(-6) = 1. The delayed success still wins, but by less. Now make the same reward stochastic. The gentle drawer policy is tried five times and gets returns 10, 10, 8, 10, and -2 because one run catches a swollen rail. The average is (10 + 10 + 8 + 10 - 2)/5 = 7.2. The yank policy gets returns -2, 4, -6, -2, and 4, averaging (-2 + 4 - 6 - 2 + 4)/5 = -0.4. A single lucky yank with return 4 should not outrank a gentler policy whose usual return is higher. A home cleaning robot gives a smaller trap. The first reward is +5 for each room marked clean and -0.1 for each minute, measured by whether the floor camera sees no dark crumbs. Trial A vacuums the kitchen for 12 minutes, leaves one coffee stain, and scores 5 - 1.2 = 3.8. Trial B sprays water over the camera view in 2 minutes, hides the dark crumbs, wets the wood floor, and scores 5 - 0.2 = 4.8. Repair the signal by adding -8 if the moisture sensor rises above 20 percent and -3 if the stain detector still reads more than 0.10 square meters. Trial B now scores 5 - 0.2 - 8 - 3 = -6.2, while Trial A scores 5 - 1.2 - 3 = 0.8. But a second loophole remains: if the robot can push crumbs under a rug, the camera reads clean, moisture stays at 12 percent, and stain area is 0, so the repaired reward still gives 4.8 for a bad room. The next repair is a new hidden-dirt check or a hard rule that forbids lifting rug edges. The reward numbers decide how much patience the learner can afford, and the rollout distribution decides how often each consequence appears.

the actual math, one level deeper

A reward function maps state and action, or a transition, to a scalar such as r(x,u,x_next). Return accumulates those scalars over time, for example G_0 = sum_t gamma^t r_t. In the cup example, the first reward is r = 10*arrived - elapsed_seconds. It ranks Trial B above Trial A because 9 > 4. Add the missing damage terms and the score changes: Trial A remains 4 because it has no force excess or damage, while Trial B becomes 10 - 1 - 0.5*(35 - 8) - 20 = -24.5. For the drawer example, the gentle trajectory has rewards [0,0,10], so G_0(gentle; gamma=1)=10 and G_0(gentle; gamma=0.5)=0+0.5*0+0.25*10=2.5. The yank trajectory has rewards [4,-6], so G_0(yank; gamma=1)=-2 and G_0(yank; gamma=0.5)=4+0.5*(-6)=1. A smaller gamma makes later rewards count less; it does not change what the real drawer needs. The RL objective is not one sampled G_0; it is J(pi)=E_{tau~p_pi(tau)}[sum_t gamma^t r_t], the expected return under the trajectory distribution created by the policy and environment. The five gentle trials estimate E[G] as 7.2, while the five yank trials estimate E[G] as -0.4. More rollouts may move those estimates because the rail snag and handle jam are random transition outcomes. This is why reward design and sampling both matter: the scalar reward says what is counted, and the trajectory distribution says how often each counted event happens. The math did not discover the real task; it optimized the written measuring stick. The boundary is literalness: if safety, smoothness, impact, energy, patience, or task quality is absent from reward or constraints, the learner can improve return by violating the designer's unstated intent.

05 · boundary

Where the idea stops working

The reward must align with the real task and safety constraints.

When that condition fails, look for this visible break: reward hacking produces high score and bad behavior.

Recognize it in a new problem: Ask what behavior the scalar feedback would encourage if exploited literally.

06 · data inside the loop

What the learner changes next

Keep the learned piece inside the control loop. The data, reward, value estimate, policy, or learned model does not act in a separate world. It reads a state or observation, helps choose an action, and that action creates the next state the learner must handle.

Ask three checks before trusting the result. What states did the data actually cover? What behavior does the reward or loss literally pay for? What happens after the learner's own first mistake changes the next input? These checks turn learning back into control instead of letting it become a vague promise that more data will fix the task.

Use the warehouse drawer case as the common run. A demonstration may show the gripper centered on the handle. A cloned policy can miss by a few centimeters, rotate the handle, and then see a state absent from the demonstrations. A reward may push for quick opening while hiding excessive force. A learned model may rehearse contacts that are slightly wrong. The controller still has to ask what state it visits, what action it issues, and what failure the learned signal can hide.
