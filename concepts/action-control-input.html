Action / Control Input

The choice the controller is allowed to make at a particular moment.

01 · the ordinary pressure

Why this idea has to exist

A planner needs to know which knobs it can turn: thrust, steering, torque, investment, braking, or a robot joint command.

The tempting shortcut is simple: Treat every desired change as directly selectable. But that shortcut breaks because a robot cannot choose its next position directly if motors only supply torques under limits.

02 · the object

What the math keeps track of

The controller keeps track of a control input, action, or policy output. This answers a practical question: separate what you want the system to do from what command you can actually issue.

The operation is concrete: Choose the input and feed it through the system dynamics.

03 · read it with your hands

What to inspect first

Point to the physical record or mathematical object before naming the method. In this concept, that object is a control input, action, or policy output. Ask what a person could measure, command, update, price, or forbid in one small run.

Now apply one command or one update. Choose the input and feed it through the system dynamics. After that operation, ask what changed in the next state, the path, the value, the constraint set, the policy, or the learned model. If nothing concrete changes, the explanation is still only a label.

The world check is the example: A drone can command rotor thrust, not instant position; the position changes only through acceleration and velocity. A reader should be able to replace that setup with another car, drone, rover, robot arm, or reward signal and keep the same control question alive.

04 · one concrete run

Work it through before naming the formula

A drone pilot may want the drone to be two meters higher. The controller cannot choose height directly. It can change rotor thrust; thrust changes acceleration, acceleration changes velocity, and velocity changes height. Calling height the action would make the plan ask for magic.

the actual math, one level deeper

The action u is the command passed into the dynamics. The next state is not chosen directly; it is produced by x_next = f(x, u).

05 · boundary

Where the idea stops working

The action set must reflect actuator limits and legal moves.

If that boundary is crossed, the visible failure is this: the plan asks for a move no actuator can produce.

Recognize it in a new problem: Separate what you want the system to do from what command you can actually issue.
