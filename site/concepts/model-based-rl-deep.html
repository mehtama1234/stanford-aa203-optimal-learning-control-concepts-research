Model-Based RL — watch and remember the world's map, then plan one route on it

The core problem (real tries are scarce or dangerous), the reframe (remember what worked from where, build a model, plan on the model instead of testing every move), a real run where ~1000 remembered transitions are enough to plan to the goal, how planning recycles every observation while trial-and-error wastes most moves, one honest weakness (if your map is wrong, your plan is confidently wrong), and the surprise (this is the seed of AlphaZero's tree search and today's world-model methods).

1 · The problem — trial-and-error wastes every move but the first

Imagine a robot that has to learn to navigate by bumping into things. It tries a move; it fails or succeeds; it tries another move; repeat. Each move teaches it one thing — 'from where I was, that action led here.' But pure trial-and-error throws away the lesson: it takes another random move, then another, backing up only one move at a time. If it takes 100 steps to find the goal once, it still has not learned anything about the steps it took in the middle — they remain mystery.

This is expensive when hardware is precious: a physical robot has 80 real tries before the bumper wears out. A rocket cannot crash 100 times to learn control. A rover on Mars cannot download new software this week. Each real step costs money, risk, or both. And yet, pure randomness or pure trial-and-error is often the only thing agents are allowed to do when they start with zero knowledge — no map, no teacher, only sensors and actuators.

The question narrows: do we have to learn only by trying more and more moves, or can we reuse what we have already tried?

2 · The reframe — stop trying moves; start remembering and planning

Here is the pivot. Instead of spending every real move on a random step or a guess, spend the first 1000 moves recording the world: from state A with action B, I ended up in state C at cost D. Collect thousands of these triples. Then build a learned model — a predictor that says 'if you are here and do that, here is where you will be.' Now, instead of testing 2000 moves on real hardware, test 2000 candidate paths inside the model. When one looks good, run only the first move on the real system, see what actually happened, add it to the data, and replan.

The gain is direct: one round of planning on the model tries hundreds or thousands of candidate paths at almost zero cost. The same limited data — say, 200 real observations — now drives a planner that evaluates 2000 imagined futures. You are trading expensive real tries for cheap imagined ones. The model-based agent multiplies the value of each observed transition.

The risk is equally direct: if your model is wrong, your plan will fail confidently. You will execute an action that looked perfect in the imagined world but crashes in the real one. This tension — memory helps, but wrong memory hurts — is the core story of model-based learning.

3 · Seen on a real run — ~1000 remembered transitions are enough to reach the goal

We placed an agent on a 9 by 9 grid with a goal and obstacles. The agent does not know where anything is; it does not know the rewards. It starts by taking 200, 500, 1000, or 2000 random steps on the real grid, recording every transition: 'at position (5,3), I moved left and ended up at (4,3) with cost 1.' It counts how many of the grid's 284 possible state-action pairs it has observed. Then, it builds a learned model of those transitions and plans a path to the goal using only that model. The outcome: did the planned path actually reach the goal when executed?

The discovered fact: once the model knows about 86% of the possible moves, a single planning pass reaches the goal. The agent saw 244 transitions out of 284 and immediately planned a correct path. A pure trial-and-error learner — one that does not plan — would need hundreds more random steps to stumble to the goal by luck. Here, one round of planning on the partial model was enough. The agent reused every one of those 1000 observations at once.

4 · Why planning recycles observations and trial-and-error does not

The numbers show a sharp difference in efficiency. A trial-and-error algorithm learns by backing up: take move 1, move 2, move 3, succeed or fail, update move 3's score, then update move 2's score using move 3's new score, then update move 1's score. Each real step teaches one move about one outcome: move 1 led to move 2. That is useful, but narrow.

Model-based planning does something richer. It says: 'I have 1000 remembered transitions. Let me imagine 1000 candidate paths through the world, each using all 1000 transitions at once.' When you plan a path, you are rolling the model forward: state 1 →model→ state 2 →model→ state 3 →model→ state 4. Every transition you learned feeds this forward roll. Then you plan 1000 different paths. Each path is free — the model is already in memory. This is why one batch of data fed to a planner achieves what would take a trial-and-error agent far more real attempts.

In simple terms: trial-and-error learns 'move 1 led to move 2' from one real step. Planning learns 'move 1 led to move 2, move 2 led to move 3, and moves 1-2-3 together reach the goal' by imagining many paths through the same data. The model is a reuse machine — it turns one observation into many lessons by imagining paths that use it.

5 · The one real weakness — wrong models make confident, expensive mistakes

This weakness is already visible in the run above. With only 200 remembered steps the map covered just 97 of the 284 possible moves, and the planned route failed to reach the goal; with 500 steps (170 of 284) it still failed. The plan is only ever as trustworthy as the map it runs on. Where the map is thin — moves the agent never tried, corners it never visited — the planner quietly fills the gaps with guesses and can route straight through them, sure of itself. It does not know what it has not seen.

This is the core danger: a learned map is only as good as the moves that built it. Plan into a region the map never saw — a rare action, an extreme state — and the planner becomes your worst enemy, following its own confident fiction straight into a wall.

The fix is receding-horizon replanning: execute only the first move, measure the real result, add that transition to the data, refit the model, and plan again. This way, new data tightens the model, and planning never strays far from the tested region. But this replan loop costs compute and time. The trade-off is real: model-based RL is sample-efficient (uses fewer real tries) but can be expensive to run.

6 · The surprise — this idea is the engine of tree search and world models

Model-based reinforcement learning looks niche: fit a small predictor on limited data, plan on it, hope the model is honest. But this idea propagates into the largest systems in modern control and machine learning.

AlphaZero-style tree search. AlphaZero plays chess and Go by building an estimated value function — a learned model of 'how good is this position?' — then running a tree search inside the estimated values. Every move in the search tree is imagined; the model makes the predictions. The tree evaluates millions of imagined futures from a single real board state. This is pure model-based planning at enormous scale.

World models for robotics. Modern diffusion-policy robots learn a dynamics model — a video generator that predicts the next camera frame given an action. Then, they plan by rolling the video model forward inside a learned value function. Do action A, watch the predicted video, does it look like a success? Do action B, check that video. This is model-based planning applied to high-dimensional vision.

Model-predictive control (MPC). The standard controller in industry and rockets is MPC: it has a known dynamics model and at each time step solves an optimization to find the best action sequence. This is planning on the real model every step — the limit of receding-horizon replanning. When the model is accurate, MPC is optimal and sample-free. Model-based RL is MPC on a learned model.

One small idea, many large applications. The pivot from 'learn only by trying' to 'remember, model, plan' is the seed of AlphaZero's search, world-model video diffusion, and classical MPC. All three trade off learned or known models against imagined futures. Master the small case — plan on a learned gridworld — and you have the architecture of strategies that beat humans and control rockets.

the run recipe — reproduce every number above

9×9 gridworld, goal (0,8), pit (4,4), 8 walls, step cost -1. Agent takes N random steps, records each transition (state, action, next-state, cost), counts known state-action pairs, fits a tabular model, plans using value iteration on the model, tests whether the planned path reaches the goal. No learning algorithm; pure planning on count data. Run with numpy.

Known transitions form a transition table T[state][action] = next_state. Model-based planner uses value iteration: V[s] ← min over actions (cost[s,a] + 0.99 * V[T[s][a]]) then extracts policy by greedy selection on T and V.
