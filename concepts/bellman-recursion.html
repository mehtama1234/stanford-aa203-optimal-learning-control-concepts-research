Bellman Recursion

The rule that today's value equals immediate cost plus the best value of the next state.

01 · the ordinary pressure

Why this idea has to exist

A controller needs a local equation that accounts for the future without listing every full trajectory.

The tempting shortcut is simple: Judge actions only by immediate cost. But that shortcut breaks because a cheap action can move the state into a costly future.

02 · the object

What the math keeps track of

The controller keeps track of a recursive equation for the value function. This answers a practical question: use it when a decision can be split into now plus the best continuation.

The operation is concrete: For each action, add current cost to the next state's value, then choose the best action.

03 · one concrete run

Work it through before naming the formula

A warehouse robot choosing between two aisles does not need to list every possible path to the loading dock. For each aisle, it can count the cost of entering that aisle now, then look up the best remaining cost from the state at the end of that move. That is the Bellman split: pay now, then inherit the future value of the state you created.

the actual math, one level deeper

V(x) = min over u of cost(x,u) + V(f(x,u)) in the deterministic case. With uncertainty, the next value is averaged over possible next states.

04 · boundary

Where the idea stops working

The recursion depends on a correct state transition and cost decomposition.

If that boundary is crossed, the visible failure is this: if the state omits hidden variables, the next-state value is not enough.

Recognize it in a new problem: Use it when a decision can be split into now plus the best continuation.
