Reachability

The set of states a system can get to, or must avoid, under allowed actions and disturbances.

01 · the ordinary pressure

Why this idea has to exist

Before optimizing a path, the controller must know which futures are even possible or unsafe.

A common wrong first move is: Assume the target is reachable because it is nearby in space. It fails when dynamics, speed, actuator limits, and disturbances decide reachability, not visual distance alone.

02 · the object

What the math keeps track of

The working object is a reachable set or backward reachable set. Use it when you need to ask whether the state can still reach safety under legal actions.

What the object does: Propagate sets through dynamics under allowed actions and possible disturbances.

03 · read it with your hands

What to inspect first

Before naming the method, point to a reachable set or backward reachable set in the setup. Ask what a person could measure, command, update, price, or forbid in one small run.

Now apply one command or one update. Propagate sets through dynamics under allowed actions and possible disturbances. After that operation, ask what changed in the next state, the path, the value, the constraint set, the policy, or the learned model. If nothing concrete changes, the explanation is still only a label.

The world check is the example: A fast car near a wall may be physically unable to stop before collision even if the wall is still several meters away. Try the same question on another car, drone, rover, robot arm, or reward signal. The concept should still name what changes, what is paid for, and what can fail.

04 · one concrete run

Work it through before naming the formula

Two cars are 5 meters apart along the road. The rear car is drifting toward the front car's lane at 0.6 meters per second, and the front car can move sideways at at most 0.4 meters per second. A one-second plan that only checks the current gap may say the front car is safe because there is still 1.2 meters of lateral space. Reachability asks a different question: if the rear car gets one bad push from wind or a steering error, is there still any legal evasive command that keeps the cars out of the collision target set? Suppose the bad target is lateral distance below 0.3 meters. If the current lateral gap is 0.5 meters, even the strongest front-car move gives 0.5 + 0.4 - 0.6 = 0.3 after one second. That state is already on the unsafe boundary. If the current gap is 0.4 meters, the same best escape leaves 0.2 meters, which is inside the target set. A state with 1.2 meters of lateral gap is outside that one-step danger set because the front car still has enough room to grow the gap to 1.0 meters under the same worst case. Now step backward one more second. From a 0.7 meter gap, the best first escape under the same bad push leaves 0.7 + 0.4 - 0.6 = 0.5. But 0.5 is already in the one-step danger set, so 0.7 is unsafe over a two-second horizon. From a 0.8 meter gap, the same first step leaves 0.6, which is outside the one-step danger set, so the car still has a safety move in this tiny model. Reachability can also mean reaching a good target. A cart at position p wants to enter a loading bay T_good = [3.0, 3.4] within two seconds. It can choose forward motion u between 0 and 0.8 meters each second, while a headwind disturbance w can subtract between 0 and 0.2 meters. From p = 1.8, choosing u = 0.8 twice gives worst-case p_2 = 1.8 + (0.8 - 0.2) + (0.8 - 0.2) = 3.0 and best-case p_2 = 1.8 + 0.8 + 0.8 = 3.4, so every disturbance lands inside the bay. From p = 1.6, the same strongest plan gives worst-case p_2 = 2.8, so the bay is not guaranteed reachable. The output is not a single heroic swerve. It is a map of starting states for a chosen horizon: below 0.5 is already bad in one step, 0.7 becomes bad over two steps, 0.8 remains outside this two-step danger map, and p = 1.8 is inside the two-step reach set for the loading bay. A wheelchair robot is 1.4 meters from an elevator door that closes in 3 seconds. It can command 0.4 m/s, but hallway crowding can subtract 0.1 m/s. The safe doorway strip after 3 seconds is [1.0, 1.2] meters from the start. Starting at p = 0.0 and commanding full speed gives best p_3 = 0.0 + 3*0.4 = 1.2 and worst p_3 = 0.0 + 3*(0.4 - 0.1) = 0.9, so the target is not guaranteed. Starting at p = 0.1 gives worst 1.0 but best 1.3, so the robot may hit the door edge. The set answer is not one middle prediction; it is the whole interval of possible next positions, with the bad edge kept visible.

the actual math, one level deeper

For an avoidance question, define the target set as collision states, for example T_bad = {gap <= 0.3 meters}. A simple one-step predecessor calculation marks a state unsafe if there exists a disturbance w such that for every legal control u, next_gap(gap,u,w) is in T_bad. The order matters: the disturbance is allowed to be bad, and the controller must fail for every legal response. With gap = 0.5, front control u can add at most 0.4 meters of lateral separation and disturbance w can remove 0.6 meters, so next_gap <= 0.5 + 0.4 - 0.6 = 0.3. That starting state belongs to the backward avoidance set A_1. With gap = 0.4, even the best control gives next_gap <= 0.4 + 0.4 - 0.6 = 0.2, which is strictly inside T_bad. With gap = 1.2, the same worst case gives next_gap <= 1.0, so it is not in this one-step bad set. The next set is built from the previous set: A_2 contains states whose worst-case next state lands in A_1. Since A_1 begins at gap <= 0.5 in this example, gap = 0.7 enters A_2 because 0.7 + 0.4 - 0.6 = 0.5. gap = 0.8 does not enter A_2 because 0.8 + 0.4 - 0.6 = 0.6, which is outside A_1. This is the backward part of backward reachability: start from the target, then repeatedly ask which earlier states can be forced into the set already known to be bad. For a goal-reaching question, the quantifiers flip: for all disturbances, there must exist a control that reaches the good target. In the loading-bay example, R_2 contains p = 1.8 because the chosen controls make the whole disturbed interval [3.0,3.4] sit inside T_good. It does not contain p = 1.6 under the same control bound because the worst endpoint 2.8 is below the target. If the target were a single point p = 3.2, the same plan would not guarantee success because different disturbances produce different endpoints. Reachability is hard because it prices the fight between control and disturbance over sets of states, not only one predicted path.

05 · boundary

Where the idea stops working

Reachability depends on a model of dynamics, controls, constraints, and disturbances.

When that condition fails, look for this visible break: a safety controller trusts an escape route that the system cannot actually execute.

Recognize it in a new problem: Ask whether the state can still reach safety under legal actions.
