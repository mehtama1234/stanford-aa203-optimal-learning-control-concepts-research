Calculus of Variations

Optimization where the unknown is an entire curve or trajectory, not a single number.

01 · the ordinary pressure

Why this idea has to exist

A controller must choose a path through time, and changing one part of the path changes the total cost.

A common wrong first move is: Optimize each point on the path independently. It fails when neighboring points are linked by dynamics and smoothness, so a path must be varied as a connected object.

02 · the object

What the math keeps track of

The working object is a functional that scores a whole curve. Use it when you need to use this lens when the decision variable is a function of time.

What the object does: Perturb the curve and require that no small admissible perturbation improves the cost.

03 · read it with your hands

What to inspect first

Before naming the method, point to a functional that scores a whole curve in the setup. Ask what a person could measure, command, update, price, or forbid in one small run.

Now apply one command or one update. Perturb the curve and require that no small admissible perturbation improves the cost. After that operation, ask what changed in the next state, the path, the value, the constraint set, the policy, or the learned model. If nothing concrete changes, the explanation is still only a label.

The world check is the example: A robotic arm path is not a pile of unrelated positions; the arm must move continuously with limited velocity and torque. Try the same question on another car, drone, rover, robot arm, or reward signal. The concept should still name what changes, what is paid for, and what can fail.

04 · one concrete run

Work it through before naming the formula

A small inspection robot must move along a 1 meter rail in 2 seconds. The decision is not one number. It is the whole velocity curve u(t) from t = 0 to t = 2. One candidate drives at 0.5 m/s for the whole trip, so x(2) = 1 meter. Another candidate surges to 0.8 m/s during the first second and slows to 0.2 m/s during the second; it also reaches 1 meter, but it spends more effort. If the path cost is J[u] = integral_0^2 u(t)^2 dt, the constant-speed curve costs 2*(0.5^2) = 0.5. The surge-then-slow curve costs 1*(0.8^2) + 1*(0.2^2) = 0.68. Calculus of variations asks a local question about curves: if I add a tiny bump epsilon*eta(t) to the entire velocity curve, while keeping the start and finish valid, does the total cost go down? If every admissible bump makes the first-order change zero or positive, the curve is a stationary candidate. The object being tested is the full signal, not one steering angle or one power setting.

the actual math, one level deeper

A functional maps a function to a number, for example J[u] = integral_0^2 u(t)^2 dt. A variation replaces u(t) by u(t) + epsilon*eta(t), where eta(t) is a small shape change and epsilon is the size of the nudge. The first variation is d/depsilon J[u + epsilon*eta] evaluated at epsilon = 0. For the rail example without dynamics beyond x_dot = u and fixed endpoint x(2)=1, admissible eta must satisfy integral_0^2 eta(t) dt = 0 so the final position does not move. The constant curve u(t)=0.5 has no first-order preference between shifting a little speed earlier and shifting the same amount later; the surge curve does, because moving effort from the 0.8 m/s part toward the 0.2 m/s part lowers squared effort. The boundary is smooth admissible perturbations: jumps, impacts, hard switching limits, and hidden state constraints can break the clean variation argument.

05 · boundary

Where the idea stops working

The approach needs smooth variations and a meaningful path-level cost.

When that condition fails, look for this visible break: ignoring path coupling creates jerky or dynamically impossible motion.

Recognize it in a new problem: Use this lens when the decision variable is a function of time.
