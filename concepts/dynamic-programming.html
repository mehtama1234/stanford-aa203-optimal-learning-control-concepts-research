Dynamic Programming

Solve a time-coupled decision problem by breaking it into state-indexed future-cost subproblems.

01 · the ordinary pressure

Why this idea has to exist

A planner needs to know which action is best now, but that depends on the best plan after the next state.

A common wrong first move is: Enumerate every possible action sequence from the start. It fails when the number of sequences grows explosively with horizon and branching.

02 · the object

What the math keeps track of

The working object is a value function over states and time. Use it when the same future subproblem appears after many different action histories.

What the object does: Work backward or iterate: combine immediate cost with the best future value after each action.

03 · read it with your hands

What to inspect first

Before naming the method, point to a value function over states and time in the setup. Ask what a person could measure, command, update, price, or forbid in one small run.

Now apply one command or one update. Work backward or iterate: combine immediate cost with the best future value after each action. After that operation, ask what changed in the next state, the path, the value, the constraint set, the policy, or the learned model. If nothing concrete changes, the explanation is still only a label.

The world check is the example: A grid-world robot chooses a move by adding the step cost to the value of the cell it will reach. Try the same question on another car, drone, rover, robot arm, or reward signal. The concept should still name what changes, what is paid for, and what can fail.

04 · one concrete run

Work it through before naming the formula

A grid rover is two cells from the charging pad. The goal cell G has value V(G)=0. The cell A just before the goal has value V(A)=1 because one legal move reaches the pad. A rough cell R has value V(R)=6 because the remaining route is slow. Now update a muddy cell M. Moving right costs 1 and reaches A, so that branch costs 1 + V(A) = 2. Moving down costs 3 and reaches R, so that branch costs 3 + V(R) = 9. Dynamic programming writes V(M)=2 and stores the right move. Now update an earlier cell S. From S, moving east costs 2 and reaches M, so that branch costs 2 + V(M) = 4. Moving south costs 1 and reaches R, so that branch costs 1 + V(R) = 7. The stored value becomes V(S)=4. The rover did not enumerate every full path from S to the charger. It solved future cells once, reused their values, and turned a long path comparison into repeated one-step comparisons.

the actual math, one level deeper

Dynamic programming solves coupled subproblems indexed by state. A deterministic update has the shape V(s) = min_a [c(s,a) + V(next(s,a))]. The backward pass starts from terminal values such as V(G)=0, writes neighboring state values such as V(A)=1, then uses those values to write earlier states such as V(M)=2 and V(S)=4. The policy is stored at the same time: pi(M)=right and pi(S)=east. This is why the transcript calls it a procedural way to solve for closed-loop policies. The price is state coverage. If the rover grid has 100 positions, 5 battery levels, and 4 load states, the table already has 100*5*4 = 2,000 state entries before actions are compared. If the state omits mud depth or battery health, the reused subproblem value is reused for states whose futures are not actually the same. Reuse is powerful only when the state is honest.

05 · boundary

Where the idea stops working

The state must summarize the future-relevant information and the transition model must be usable.

When that condition fails, look for this visible break: the state space becomes too large or the model is wrong.

Recognize it in a new problem: Use it when the same future subproblem appears after many different action histories.
