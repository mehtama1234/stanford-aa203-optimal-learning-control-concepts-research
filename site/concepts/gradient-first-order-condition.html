Gradient and First-Order Condition

A local test for whether a tiny move can immediately improve the objective.

01 · the ordinary pressure

Why this idea has to exist

An optimizer needs a direction that says which small change makes the score better or worse.

A common wrong first move is: Try random changes until the cost goes down. It fails when random search wastes structure and becomes expensive in high-dimensional control trajectories.

02 · the object

What the math keeps track of

The working object is a gradient, derivative, or stationarity condition. Use it when tiny changes to a decision have meaningful, computable effects.

What the object does: Differentiate the objective and look for directions of improvement or stationarity.

03 · read it with your hands

What to inspect first

Before naming the method, point to a gradient, derivative, or stationarity condition in the setup. Ask what a person could measure, command, update, price, or forbid in one small run.

Now apply one command or one update. Differentiate the objective and look for directions of improvement or stationarity. After that operation, ask what changed in the next state, the path, the value, the constraint set, the policy, or the learned model. If nothing concrete changes, the explanation is still only a label.

The world check is the example: If increasing steering torque slightly reduces path error but increases actuator cost sharply, the gradient exposes the tradeoff. Try the same question on another car, drone, rover, robot arm, or reward signal. The concept should still name what changes, what is paid for, and what can fail.

04 · one concrete run

Work it through before naming the formula

A rover is choosing one steering correction z in degrees for the next planning snapshot. The written cost is J(z) = (z - 3)^2 + 0.2*z^2: miss the desired 3 degree turn, but also avoid using too much steering. At z = 0, the slope is dJ/dz = 2*(0 - 3) + 0.4*0 = -6. A tiny positive move, delta z = +0.1, is predicted to change cost by about -6*0.1 = -0.6, so the rover should move right. At z = 2.5, the slope is dJ/dz = 2*(2.5 - 3) + 0.4*2.5 = 0. The first-order test says that, to first order, a tiny move left or right does not lower the cost. Check the numbers: J(2.4) = (2.4 - 3)^2 + 0.2*2.4^2 = 1.512, J(2.5) = 1.5, and J(2.6) = 1.512. The point is locally best for this smooth one-variable score. But if a rock begins at steering above 2.3 degrees and the cost forgot collision, the gradient condition can be satisfied while the rover still hits the rock.

the actual math, one level deeper

First-order reasoning starts with the small-displacement formula from the transcript: J(z + delta z) is approximately J(z) + grad J(z)^T delta z. If some legal delta z makes grad J(z)^T delta z < 0, then that move lowers cost to first order, so z is not a local minimum. For an unconstrained smooth local minimum, every tiny direction is legal; the only way to avoid a downhill direction is grad J(z) = 0. With constraints, the condition changes: downhill directions that leave the legal set do not count. At a boundary such as z <= 2.5, a positive move may be illegal, so a nonzero gradient can still be consistent with a constrained local minimum. The test tells you where to look next, not where to stop thinking. The boundary of the idea is localness: grad J = 0 is a filter for candidates, not proof of global optimality, safety, or mission success.

05 · boundary

Where the idea stops working

Gradient reasoning is local and depends on smoothness and the chosen coordinates.

When that condition fails, look for this visible break: the method stops at a local stationary point that still violates the real safety or mission goal.

Recognize it in a new problem: Use it when tiny changes to a decision have meaningful, computable effects.
