Direct Transcription

Turn a continuous trajectory problem into a finite optimization problem over many time-grid variables.

01 · the ordinary pressure

Why this idea has to exist

A computer cannot optimize over infinitely many points of a curve, so the curve must be represented by a finite set of decision variables.

The tempting shortcut is simple: Optimize only the start and end points. But that shortcut breaks because the path between them may violate dynamics, obstacles, or actuator limits.

02 · the object

What the math keeps track of

The controller keeps track of a discretized trajectory with state and action variables at grid points. This answers a practical question: use this when the path is the object and a nonlinear optimizer will solve the finite version.

The operation is concrete: Add constraints that force neighboring grid points to approximate the dynamics.

03 · one concrete run

Work it through before naming the formula

A robot arm path is a smooth curve, but a solver needs a finite list of numbers. Direct transcription places dots along the path: joint angles, velocities, and commands at selected times. Then it adds constraints saying neighboring dots must be connected by the dynamics. The solver chooses the dots; the engineer checks whether the space between dots hid trouble.

the actual math, one level deeper

The continuous path becomes decision variables x_0...x_N and u_0...u_N. Defect constraints enforce x_{k+1} minus the dynamics step from x_k and u_k.

04 · boundary

Where the idea stops working

The discretization must be fine and accurate enough for the motion being planned.

If that boundary is crossed, the visible failure is this: a coarse grid hides collisions, unstable transitions, or excessive actuator demands.

Recognize it in a new problem: Use this when the path is the object and a nonlinear optimizer will solve the finite version.
