Dynamic Programming

Solve a time-coupled decision problem by breaking it into state-indexed future-cost subproblems.

01 · the ordinary pressure

Why this idea has to exist

A planner needs to know which action is best now, but that depends on the best plan after the next state.

The tempting shortcut is simple: Enumerate every possible action sequence from the start. But that shortcut breaks because the number of sequences grows explosively with horizon and branching.

02 · the object

What the math keeps track of

The controller keeps track of a value function over states and time. This answers a practical question: use it when the same future subproblem appears after many different action histories.

The operation is concrete: Work backward or iterate: combine immediate cost with the best future value after each action.

03 · one concrete run

Work it through before naming the formula

A grid-world robot chooses a move by adding the step cost to the value of the cell it will reach. the actual math, one level deeper

The mathematical object is a value function over states and time. The operation is: Work backward or iterate: combine immediate cost with the best future value after each action. The boundary is: The state must summarize the future-relevant information and the transition model must be usable.

04 · boundary

Where the idea stops working

The state must summarize the future-relevant information and the transition model must be usable.

If that boundary is crossed, the visible failure is this: the state space becomes too large or the model is wrong.

Recognize it in a new problem: Use it when the same future subproblem appears after many different action histories.
